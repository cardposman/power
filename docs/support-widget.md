# 통합 상담 위젯 연결

- 운영 주소: https://tstudymate.com
- 사이트 ID: `tstudymate` — 일본어·영어 공통
- 관리자 표시 이름: TS맨투맨회화
- 공통 위젯: https://lxrjy-92bbd.web.app/widget.js
- 공개 설정: https://lxrjy-92bbd.web.app/config.json

2026-11-17에 chat 프로젝트의 `docs/integrations/tstudymate.md`, 공통 README와 `snippets/tstudymate.js`를 기준으로 연결했다. Firebase·인증·공통 위젯 소스는 이 저장소에서 관리하지 않는다.

## 설치와 생성

`assets/js/site.js` 끝의 독립 IIFE 한 개가 정확한 운영 Origin에서만 공통 위젯을 불러온다. 로컬·file 미리보기는 제외하며 운영 인증 정책을 완화하지 않는다. 기존 loader ID 또는 위젯이 있으면 추가하지 않는다. 별도 외부 script 태그는 템플릿에 넣지 않는다.

일본어 504개와 영어 500개, 총 1,004개의 콘텐츠·목록 페이지가 공통 JS를 한 번씩 사용한다. 이전 경로 호환용 리다이렉트는 안내 페이지로 이동한 뒤 적용된다. 네이버 일본어·영어 상담 링크, 메뉴와 학습 과정 탭은 유지한다.

`templates/lesson.html`, `english-lesson.html`, `category.html` 및 두 언어 목록 생성기는 공통 JS/CSS의 내용 해시를 URL에 넣는다. `scripts/shared-assets.cjs`가 버전을 계산하므로 JS/CSS 변경 후 전체 페이지 재생성 시 새 버전을 읽는다. 소스는 기존 지역별 폴더에 보관하고 짧은 공개 경로는 `_site/` 빌드에만 생성한다.

## 배치

제공된 삽입 코드가 `.fixed-contact`의 보이는 높이를 읽어 `--support-bottom`을 높이 + 16px로 설정한다. 고정바의 크기 변경, 스크롤, 창 크기 변경에도 다시 계산한다. `site.css`의 `--support-right`는 중앙 480px 페이지의 오른쪽에 맞추고 좁은 화면에서는 기본 12px에 세로 스크롤바 폭 보정을 적용한다. 공통 패널의 `100vw` 폭이 실제 레이아웃보다 커질 때 좌우로 나눠 여백을 줄여 테두리도 화면 안에 유지한다. 위젯 내부 Shadow DOM과 공통 CSS는 수정하지 않는다.

공통 패널의 높이 제한과 내부 스크롤은 공통 위젯에서 제공한다. 검사에는 패널뿐 아니라 입력창·전송·닫기 버튼의 화면 내 위치와 클릭 가능 여부도 포함한다. 브라우저 화면 크기 검사는 실제 휴대폰 소프트웨어 키보드·물리적 알림 검증을 대신하지 않는다.

## 검증과 실제 상담

`node --test scripts/test-support-widget.cjs`는 외부 통신 없이 Origin 제한, 중복 방지, DOM 준비, 하단 여백, 기존 메뉴, 전체 페이지의 단일 공통 JS를 확인한다. 기존 workflow의 검증 목록에도 포함한다. 기존 페이지·영어 원고·경로 검사도 유지한다.

실제 운영 검증 결과와 적용 commit은 작업 완료 보고에 기록한다. 운영 주소에서 사이트명·연결·입력 활성화를 확인한 뒤 사용자가 관리자 휴대폰을 준비했다고 알려주면 사이트명이 포함된 테스트 메시지 **한 번**만 보낸다. 테스트 전에 메시지나 알림을 발생시키는 자동 반복 검사를 하지 않는다.

2026-11-17 실제 상담 확인 결과:

- TS맨투맨회화로 분류: **사용자 휴대폰 확인 완료**
- 휴대폰 알림 도착 및 알림에서 해당 상담방 이동: **사용자 확인 완료**
- vending 상담과의 분리: **사용자 관리자 앱 확인 완료**
- 테스트 고객 메시지: `TS맨투맨회화 연결 테스트 · power 운영 사이트 확인입니다.`를 **한 번** 전송. 고객 웹에 전송 완료와 고객 메시지 1건을 확인했다.
- 관리자 앱의 `power 답장 확인`이 고객 웹에 **새로고침 없이 실시간 표시**됐다.
- 새로고침 후 상담창을 다시 열었을 때 동일한 고객 메시지 1건·관리자 답장 1건과 입력 활성화를 확인했다.
- PC·브라우저 모바일 배치: 1440×900, 390×844, 390×480, 320×480, 390×400, 568×320, 390×300에서 패널과 입력·전송·닫기 버튼이 화면 안에 있고 기존 하단 네이버 상담바 위에 놓임을 확인했다. 닫기와 다시 열기도 실제 클릭했다. 짧은 화면(390×400)에서 테스트 메시지 전송 버튼이 실제로 동작했다.
- 실제 고객 휴대폰의 소프트웨어 키보드 배치는 이번 데스크톱 브라우저 크기 검사와 별도다.

적용 코드: 최초 설치 `ee5528e`, 좁은 스크롤 화면 보정 `31dc2fac`. GitHub Actions의 생성·검증·배포가 성공했다. 증거 화면과 상세 치수는 로컬 ignored `verification/widget/`에 보관하며 상담 메시지나 인증 상태를 공개 저장소의 이미지로 올리지 않는다.

운영 브라우저 확인 경로: `/`, `/english/`, `/reg-yongsangu/`, `/en-reg-yongsangu/`, `/st-seomyun/`, `/en-st-seomyun/`, `/course/travel/`, `/region/`, `/english/station/`. 모두 loader·위젯 각 1개, `tstudymate` ID, TS맨투맨회화 표시, 입력 활성화와 기존 언어별 네이버 링크를 확인했다. 대표 9개 URL의 공개 HTML과 공통 JS도 빌드 결과와 일치했다. 페이지 끝까지 스크롤한 상태에서도 런처와 하단 고정바 사이 16px를 확인했다.

로컬 기존·추가 단위 검사 28개, 일본어·영어 대표 브라우저 검사 각 7개 폭, 전체 소스·배포 링크 검사와 영어 개별 원고 검사, 수정 후 전체 페이지의 단일 공통 스크립트 검사를 통과했다. 최종 운영 화면에서는 신규 고객 테스트 메시지가 1건인 상태를 유지했다.

연속 하위 페이지 검사에서는 공통 서버의 고객 UID별 `open` 제한(고정 1분 구간당 5회)을 확인했다. 기존 상담 복원도 `openChat` 호출로 계산되어 여섯 번째 연속 열기에서 429와 `전송이 많습니다. 잠시 후 다시 시도해 주세요.`가 표시될 수 있다. 이는 추가 메시지 전송을 뜻하지 않는다. 보안 설정을 유지하고 다음 구간에 `다시 연결`을 눌러 입력 활성화와 동일 대화 복원이 정상임을 확인했다. 정책·오류 문구 변경이 필요하면 chat 프로젝트의 `firebase/functions/src/core.ts`에서 관리한다.

인증이나 서버 문제를 발견하면 원인과 필요한 변경을 chat 프로젝트에 전달하며, 관리자 비밀번호·개인 토큰·서비스 계정은 이 저장소에 저장하지 않는다.

## 되돌리기

공통 JS 끝의 위젯 IIFE를 제거하고 페이지를 재생성·배포한다. 필요하면 위젯 정렬용 CSS도 제거한다. 접수된 상담이나 Firebase 데이터는 삭제하지 않는다.
